Iggy cluster

Three Iggy nodes in Docker, kept consistent by Viewstamped Replication. Stop a node and the others carry on without it: stop the leader and a follower takes over. Start it again and it catches up. Node 1 serves TCP on localhost:18090, where the other tabs connect, so their producers and consumers run against the cluster once it is up.

Messages stored

Messages each node holds, last 60 seconds. A follower's line tracks the leader's; a stopped node's line breaks, and when it starts again it climbs back as it catches up.

What happened

Nodes starting and stopping, leader changes and followers catching up, newest first. A restarted node replays the messages it missed, so it writes faster than the leader until it is back in step. Message counts differ a little between nodes because each node's retention deletes old segments on its own schedule.
